#### 项目背景

该项目面向 LDV 设备的脉搏波/ECG 采集场景，实现串口设备控制、实时波形展示、信号质量检测、滤波处理与测量数
据保存，解决实验/检测过程中数据采集流程不稳定、质量判断依赖人工的问题。

#### 技术栈

FastAPI / Uvicorn / PySerial / NumPy / SciPy / React / Vite / Ant Design / ECharts / SSE

#### 个人职责 / 核心功能

负责前后端核心流程设计与实现，包括串口设备连接校验、采样参数下发、光源控制、实时数据采集、SSE 数据推流、
波形渲染、滤波配置、质量检测、测量状态机、自动停采、数据保存和运行日志模块。

负责将原 Node 后端重构为 Python FastAPI 后端，并保持原有 /api/... 接口契约兼容，保证前端无需大规模改造即
可接入新的采集与信号处理逻辑。

实现 LDV 设备协议封装，支持\*IDN? 设备识别、SamR/SamD 采样配置、Acqu/STOP 采集控制、激光器开关、电流到电
压转换等核心指令流程，并对设备 ACK 返回进行校验。

实现测量流程状态机，区分质量检测模式与正式采集模式：质量检测阶段使用固定采样参数循环采集，正式采集阶段恢
复用户配置并按采样率/采样深度自动计算采集时长、自动停止并允许保存。

#### 数据错位

串口数据同时包含文本应答和二进制采集流，直接在接口中读取容易阻塞服务并造成数据错位。
采用独立 SerialService 封装串口通信，通过后台线程持续读取串口数据，按当前模式区分文本行解析和 9 字节二进
制帧解析，再回调到 FastAPI 事件循环。这样避免阻塞 asyncio，同时保证配置命令和实时采集互不干扰。

#### 滤波难题

实时滤波需要足够上下文，否则会产生明显边界效应，影响波形判断。
后端按 GUI 原逻辑固定使用 1kHz 逻辑采样率，维护 7 秒环形窗口，满窗口后再执行 Butterworth 零相位滤波，并只
展示中间 5 秒有效窗口。这样既保留实时性，又减少滤波边缘失真。

#### 质量检测实现

质量检测需要从连续波形中自动判断信号是否可用于正式采集。
实现基于滤波后波形的自相关质量评估流程，对最近 5 秒窗口进行幅值、峰值和连续有效次数判断，两个通道均满足阈
值后才允许从质量检测切换到正式采集，同时提供强制采集入口应对现场特殊情况。

#### 标准收尾

测量流程容易出现自动停采、手动停止、页面关闭、设备释放等状态不一致问题。
设计统一的测量收尾函数 finalize_measure_session，集中处理停止采集、清理定时器、刷新缓存、设置可保存状态；
页面关闭时调用设备释放接口，依次关闭红光、关闭电流源、停止采样并写入运行日志。

#### 项目成果

- 实现 20+ 个后端 API 接口，覆盖设备管理、采集控制、滤波、质量检测、测量保存和日志模块。
- 支持 10K～1M Hz 采样率、10K～3M 采样深度配置，并根据采样率和采样深度自动计算采集时长。
- 实现 1kHz 逻辑采样率下的实时波形处理，支持 7 秒滤波上下文、5 秒实时展示窗口和停测后整段历史数据重滤波。
- 完成前端、后端、串口设备协议、实时推流和本地 NDJSON 文件保存的完整闭环，项目可在 Windows/Linux 环境下启动联调。
